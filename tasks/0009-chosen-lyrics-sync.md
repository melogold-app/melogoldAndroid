# Выбранный текст песни переезжает на другие устройства (и не стирается)

Статус: открыто

**Срочно, раньше остальных открытых заданий.** Windows 0.1.10 отправляет на сервер текст, выбранный в «Найти другой
текст», с его настоящим источником (`lrclib`). Android принимает такую версию, не считает её своей и при следующей
выгрузке **удаляет её с сервера** — выбор пользователя пропадает на всех устройствах (Windows у себя его теперь
сохраняет, но синк ломается).

Те же задания: `melogoldWindows` (сделано, Windows 0.1.10, коммиты `262c146`, `845d1de`),
`melogoldiOSmacOS/tasks/0011-chosen-lyrics-sync.md`, `melogoldLinux/tasks/0002-chosen-lyrics-sync.md`.

## 1. Что нужно пользователю

Пользователь добавил трек в Избранное на телефоне, нашёл для него правильный текст в «Найти другой текст» (LrcLib), а
на Windows пришлось искать тот же текст ещё раз: выбор не переехал. Свои набранные и импортированные тексты
переезжают — не переезжает только выбранный из стороннего источника.

## 2. Решение (одинаково на всех клиентах)

API §4.10 это уже разрешает: свои тексты пользователя — «набранные и синхронизированные в редакторе, импортированные из
файла **или выбранные вместо найденного автоматически**»; источники `user | file | youtube_music | lrclib | kugou`.
Контракт не меняется.

1. **Флаг «выбран»** у локального текста трека (новая колонка, по умолчанию `false`).
2. **Выбран = свой:** текст свой, если одна из сторон из `User`/`File` **или** стоит флаг и текст не пустой. Такой
   уходит на сервер (`PUT /auth/me/lyrics/{videoId}`) со своим настоящим источником (`lrclib`, `youtube_music`, `kugou`).
3. **Флаг ставится:**
   - пользователь выбрал текст в «Найти другой текст» (`LrcLibSearchDialog`, `ModernPlayer.kt` ~657);
   - пришла своя версия с сервера (`LyricsSync.apply`, а также ответ `mine` в цепочке поиска) — **с любым источником**:
     раз она на сервере в «своих», её выбрали или набрали на другом устройстве;
   - найденный здесь автоматически текст совпал с пришедшей своей версией — он становится выбранным.
4. **Флаг снимается:** пользователь выбрал «Найти другой текст» → другой вариант (флаг остаётся, меняется текст) или
   сбросил текст к найденному автоматически (флаг `false`, на сервер уходит удаление).
5. **Найденный автоматически** (флаг `false`, источник не `User`/`File`) по-прежнему на сервер не уходит: его найдёт и
   другое устройство.
6. **Правка в редакторе** выбранного текста делает сторону `User`, как и раньше.

## 3. Android

- `models/Lyrics.kt`: поле `chosen: Boolean = false` в `Lyrics`; миграция Room 36 → 37
  (`ALTER TABLE Lyrics ADD COLUMN chosen INTEGER NOT NULL DEFAULT 0`), схема в `schemas/`.
- `isOwn` сейчас только `User || File` (`models/Lyrics.kt:28`); `Lyrics.ownContent()` в `sync/LyricsSync.kt` —
  добавить «или `chosen`». `Database.ownLyricsNow()` (строка ~1161) — отбирать и выбранные.
- `LyricsSync.apply`: `content.toLyrics(videoId)` → с `chosen = true`. Сейчас версия с источником `lrclib`
  записывается, а `pendingUploads` не находит её среди своих и отправляет `DELETE` — это и стирает выбор с Windows.
- Выбор в `LrcLibSearchDialog` → `chosen = true`.
- `LegacyImporter` (копия ViTune) — `chosen = false`, как было.

## 4. Проверка

- **Юнит-тесты:**
  - выбранный LrcLib — свой, `PUT` с `syncedSource = "lrclib"`;
  - тот же текст без флага — не свой, не отправляется;
  - версия с сервера с источником `lrclib` → сохраняется с флагом и **не** попадает в `DELETE` при следующей выгрузке;
  - миграция 36 → 37 сохраняет тексты, флаг `false`.
- **Живой сервер** (временный аккаунт, удалить после): Windows выбирает LrcLib-текст → Android получает его, после
  синка версия на сервере жива (`POST /auth/me/lyrics/changes` не отдаёт надгробие); и обратно — выбор на Android
  появляется на Windows.
