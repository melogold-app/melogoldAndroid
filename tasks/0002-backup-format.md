# Копия библиотеки в общем формате и «где мои треки» после импорта

Статус: сделано

Общий формат копии и правила импорта — `docs/spec/backup-format.md`. Те же задания для Windows (`melogoldWindows/tasks/0004-import-export.md`) и Apple (`melogoldiOSmacOS/tasks/0006-import-export.md`).

## 1. Что нужно пользователю

- Копия с Android открывается на Windows и Apple, и наоборот, без потерь: свои тексты остаются своими, плейлисты находят себя.
- После импорта из ViTune сразу видно, куда попали треки. Пользователь из ViTune после импорта написал «всё ещё только Избранное видно»: вкладки «Песни» у нас нет, её роль играет «История › Чаще всего» (FEATURES, «Вкладка „Песни“»), а найти это не с чего.

## 2. Решение

- **Импорт:**
  - читает `Lyrics.fixedSource`/`syncedSource` из копии;
  - плейлист сначала ищется по `syncId` (спецификация, раздел 3).
- **Экспорт:**
  - снимок через `VACUUM INTO` (API 30+), до API 30 — копия файла под блокировкой записи;
  - в копии метка `MelogoldBackup` и `journal_mode=DELETE`.
- **Настройки › База данных:** «Сохранить копию» и «Импорт копии», как у Windows и Apple.
- **Итог импорта:** кнопка «Открыть историю».
- **Библиотека:** на карточке «История» — число треков в истории, как у «Избранного» и «Скачанного».
- **Итог импорта:** треки и тексты считаются только у тех треков, что видны в библиотеке. В копии друга было 1330 треков, из них 1132 — кэш открытых альбомов ViTune; итог «новых треков — 1300» при 198 прослушанных сбивал с толку.

## 3. Проверка

- `LegacyImporterTest`:
  - источники текстов и `syncId` плейлиста переживают круг «экспорт → импорт»;
  - в копии есть метка.
- Эмулятор: импорт, «Открыть историю», число на карточке.
