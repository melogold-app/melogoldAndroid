# Журнал: срок хранения и выключение

Статус: сделано (31.10.2026), не выпущено; на телефоне не проверено (Pixel не подключён).

Максим (31.10.2026): «чтобы можно было выбрать, сколько долго хранятся логи, и выключить логирование совсем — на всех
платформах». Его выбор: сроки «День · 3 дня · Неделя · Месяц», при выключении записанное удалить сразу.

## Как устроено (так же у Linux 0037 и Windows 0040)

- «Настройки → Прочее → Поиск и устранение неисправностей»: «Журнал» (по умолчанию вкл), «Хранить» (день, 3 дня,
  неделя — по умолчанию, месяц), «Показать журнал» — недоступны, пока журнал выключен. `DataPreferences.logEnabled`
  (`logs.enabled`), `logRetentionDays` (`logs.retentionDays`).
- `LogFiles` (0035) пишет не в `current/previous/older.log`, а в `files/logs/melogold-ГГГГММДД-ЧЧММСС.log` (местное
  время начала файла); новый — после 2 МБ или со сменой даты. Падение (необработанное исключение) — `last-crash.txt`.
- Уборка — при старте, с каждым новым файлом и при смене срока: старше срока — удаляются, затем, если папка больше
  50 МБ, — самые старые; пишущийся файл не трогается. Файлы 0.1.22 — тоже `*.log`, уходят по сроку.
- Выключили — logcat-поток останавливается, папка пустеет сразу; плеер перестаёт писать своё состояние и события
  `EventLogger`. Включили — новый файл сразу, и с текущего момента (`logcat -T`): строки до выключения, которые ещё
  лежат в системном буфере, обратно на диск не попадают. Системный logcat самого Android приложение выключить не может:
  это память системы, она перезаписывается сама.
- «Поделиться» в журнале: шапка (+ «Журнал: хранить N дн.»), падение, затем все файлы от старых к новым под
  `===== melogold-20261031-134500.log =====`.
- В русской локали переведено «Показать журнал» (`show_logs`; было «View debug logs»).

Тест `LogFilesTest`: уборка по сроку и по 50 МБ, порядок разделов.
